# llm-column-extract

从 OCR 产出的 Markdown 文本里提取**列名**的 LLM 组件。

> **状态：已实现（规格 `docs/specs/2026-10-05-column-extract-design.md`）。** 本文件顶部的
> 「理解」段落是设计对话的产物，权威描述以规格为准；下面新增的「运行」一节是实际交付的
> 用法与依赖。

## 依赖与安装

| 依赖 | 什么时候需要 | 缺了会怎样 |
|---|---|---|
| **Python ≥ 3.10** | 总是（用到 `X \| None` 这类注解与 `from __future__ import annotations`） | 装不上 |
| **`langchain-openai`** | **只有真实调用模型时**（`pip install langchain-openai`） | 见下 |

- **纯标准库**：本组件的其余部分（输入解析、提示词、模型输出兜底解析、编排、md 渲染、
  CLI）不依赖任何第三方包，只用 `json` / `argparse` / `dataclasses` / `unittest`。
- `langchain-openai` 的 import 是**惰性**的：只在 `client.LangChainClient.__init__` 里
  `from langchain_openai import ChatOpenAI`。所以**没装它也能 import 本组件、也能跑全部
  单元测试**（测试走 `tests/_fake_client.py` 的假 client，规格 §10「模型调用不进单元测试」）。
- **缺 `langchain-openai` 时的行为**：真跑（不注入假 client）时，`python -m llm_column_extract`
  在 stderr 上打一句「造不出模型客户端（缺少 langchain-openai，请先安装（pip install
  langchain-openai）…）」并**返回退出码 2**，stdout 一个字都没有、不写任何产物。
  **导入期不会报** —— 只 `import` 本组件不会因为缺它而失败。
- 换模型、换网关都不需要改代码：网关是否支持 `response_format`（结构化输出）**不在依赖里**
  （规格 §8），代码侧本来就有兜底解析。

## 运行

```
python -m llm_column_extract <input.jsonl> [-o <dir>]
```

（在本仓库里跑要先把 `src` 放进 `PYTHONPATH`；`-o` 缺省是当前目录。）

**两份产物，都强制产出**（规格 §8）：

| 产物 | 给谁 | 说明 |
|---|---|---|
| `<name>.out.jsonl` | 机器 | 一行一条记录，逐表不拍平 |
| `<name>.out.md` | 人 | 由**代码**从 jsonl 渲染（规格 §11.3），不由模型生成 |

两份都是 UTF-8、`newline="\n"`。`<name>` 是输入文件名的 **stem（去掉最后一个扩展名）**：
`batch.jsonl` ⇒ `batch.out.jsonl` / `batch.out.md`；没有扩展名的 `ocr/batch` 也一样是
`batch.out.jsonl` / `batch.out.md` —— 两份产物共享同一个 `<name>`（规格 §8）。

**配置全部来自环境变量**（规格 §8）：

| 环境变量 | 必填 | 缺省 | 说明 |
|---|---|---|---|
| `LLM_MODEL` | ✅ | — | 模型名 |
| `LLM_BASE_URL` | ✅ | — | 内网 OpenAI 兼容网关的 `base_url` |
| `LLM_API_KEY` | ❌ | 空串 | 私有化网关常常不校验；真实调用需要时才给 |
| `LLM_TIMEOUT` | ❌ | `60` | 秒；`0` 表示**不设超时**（代码把它映射成客户端的不限时，而不是 0 秒 —— httpx 的 `timeout=0` 会让每次调用立刻超时） |
| `LLM_MAX_ATTEMPTS` | ❌ | `2` | 每张表对模型调用的次数上界（= 第一次 + 重问一次） |

**缺必需项 / 数值不合法** ⇒ stderr 上报错（点名哪个变量）、**退出码 2**、不写产物。
**串行执行**，不做并发（规格 §9 最后一段）。

**五种结局**（规格 §9：**整批跑完退出码非 0，但产物照写** —— 与 `excel-to-md` 的取舍刻意不同）：

| 结局 | 产物 | stdout | stderr | 退出码 |
|---|---|---|---|---|
| 全好 | 两份都写 | 一行摘要 | 空 | `0` |
| 有记录级或表级失败 | **两份照写** | 一行摘要 | 逐条诊断 | `1` |
| 文件级故障（读不了 / 空文件 / 整体解码失败） | 不写 | 空 | 一条错误 | `3` |
| 配置不全、客户端造不出来 | 不写 | 空 | 一条错误 | `2` |
| 产物写不下去（盘满、没有写权限……） | 尽力 | 空 | 一条错误 | `4` |

退出码 `2` **同时覆盖用法错误**（认不出的参数、没给 `input` —— argparse 自己的约定）与
配置/客户端错误：两者都是「启动前就停了、一个产物都没写」。

诊断**一律走 stderr**；stdout 只有调用方会拿去管道的那一行摘要。

## 它做什么

读入一份 jsonl，逐条用 LLM 从 OCR 文本里提取列名，写出另一份 jsonl。

| | |
|---|---|
| 输入 | 一条记录 = 一个 `(文件, 工作表)`，含该工作表的 OCR Markdown 文本 |
| 输出 | 一条记录 = `{ID, FileName, sheet, columns}` 形态的列名 |
| 用到的框架 | **LangChain** |

## 明确**不在**范围内

- **下游怎么用这份 jsonl**：你说「会有下一步动作，暂时不需要考虑」。所以本组件只负责
  把它写出来，不负责消费它。
- **OCR 本身**：那是另一条链路（会处理 PDF 等我们读不了的形式），不在本组件里。
- 任何与 `excel-to-md` 的耦合：见下。

## 与 `excel-to-md` 的关系：**无直接关联**

这是一个独立的组件，刻意放在**工作区根目录**、与 `excel-to-md/` **平级**，而不是放在它
里面。原因不是审美，是 git：

> `excel-to-md/` 是通过 `git subtree split --prefix=excel-to-md` 发布到
> GitHub `AidonQ/excel-to-md` 的。任何放进那个目录的文件都会**被一起推上去**。
> 放在平级目录就不会。

两边的关系只有一个方向、而且是可选的：`excel-to-md` 的 `validate` 子命令**能**读本组件
产出的 jsonl 并给它打分。那是 `excel-to-md` 那边**已经存在**的能力，本组件不需要知道它。

## 术语：必须用 `excel-to-md/GLOSSARY.md` 的权威词

`excel-to-md` 的 `AGENTS.md` 声明 `GLOSSARY.md` 是术语的唯一权威。核对结果：

| 权威词 | 含义 | **明令避免** |
|---|---|---|
| **标题行区** | 一个表顶部被判定为表头的**连续行块**，可以为 0 行，**用起止行号表示，不用布尔值** | ~~表头~~、~~列名行~~、~~标题~~ |
| **数据区** | 标题行区以下 | ~~内容区~~、~~正文~~、~~表体~~ |
| **表范围** | A1 记法的矩形，如 `A3:C42` | ~~边界~~、~~尺寸~~、~~区域~~ |

⇒ **提示词里不得出现「表头」「列名行」「标题」这三个词。** 用「标题行区」，并在提示词里
**当场给一句可判定的定义**（模型不认识这个生造词，必须解释）。

⇒ 「列名取哪一行」这件事在权威词汇里没有独立术语：它就是**标题行区的最下面一行**。
输出 `columns` 的取值来自它，`path` 来自标题行区各层。

⇒ `header_rows` 用**起止行号**而不是布尔值 —— 与 `excel-to-md` 的 sidecar 一致。

## 产出契约 ★ 这是本组件要写出来的东西，别弄丢

**两份产物，都强制产出：**

- **jsonl** —— 给机器读（下述形状）
- **md** —— 给人读。人看的是 md，不是 jsonl（这是你明确说的分工）

单条 jsonl 记录：

```json
{
  "ID": "...",
  "FileName": "...",
  "sheet": "...",
  "tables": [
    { "range": "A2:C4", "columns": ["产品", "数量", "单价"] }
  ]
}
```

- **逐表**，不是拍平。拍平形状在验证器那边判 `partial`、覆盖率 0%；逐表能逐表核验
- **`columns` 的元素是 `path`（全路径）**，不是最下层的 `name`。单层表头时两者相同
  （`"产品"`）；两层时是 `"2024 年度 / Q1"`。分离符为 `" / "`。
  验证器对每列 `name` 与 `path` **两种都试**，所以这形状能对上，且它自带分组信息
- 没有表头的表：`columns: []` —— **必须给空数组，不能省掉这个字段**。省掉会被判成格式错误
- 诊断字段（模型名、提示词版本、重试次数、模型的 reason）**直接放在记录里**：
  `load_claimed` 只读它认识的键、忽略多余的键，所以加字段不会破坏契约
- 认的别名：`tables`/`Tables`、`range`/`Range`、`columns`/`列名`、`sheet`/`Sheet`

### ⚠️ 硬约束：`columns` 的元素必须是**字符串**

`excel-to-md` 的 `load_claimed` 对 `columns` 的每一项执行 `str(entry)`。如果写成
`{"name": "Q1", "path": "..."}` 这种对象，会被**字符串化成一坨 `"{'name': 'Q1', ...}"`**
—— 列名全部错掉，而且**不会报错**（它只校验形状、不校验内容）。

所以：`columns` 只能是字符串数组。多层表头的 `path` 若要单独给，放**别的字段**
（`load_claimed` 会忽略它）。

### 诚实记录的一条取舍

「纯提示词」⇒ 列名由模型写出 ⇒ **本组件无法自动判断某个列名是不是编的**（没有
「原文里有没有这个词」这一步）。对真实 `.xlsx` 来源无所谓（`excel-to-md` 会拿真值核），
对 PDF 来源则失去这道防线。这是明确接受的取舍，不是疏漏。

## 已定（来自设计对话）

1. **提示词从零设计**（选项 C）。没有现成提示词可复用。
2. **输入形态 ≈ 本项目 `.md` 的 Markdown 表格**（伙伴的 OCR 输出与它类似），**不是**一坨纯文本。
   所以模型要做的是**读表头**，而不是重新推断表结构 —— 任务的难度因此低了一档。
   可直接从语法推出来的信息：`---` 分隔线**之前**的行是表头行；表格上方有带范围的标题。
3. **多层表头 / 合并单元格：采用「重复取值」**，而不是本项目 `.md` 里的 `[←M←]` / `[↑M↑]` 标记。
   ⇒ 提示词不必教模型解析标记、向左继承。
   ⇒ **但这同时也意味着本项目 `.md` 不是本组件的输入形状**（它用标记、不重复）。
   ⇒ **待与伙伴确认**：是 OCR 本来就重复取值，还是需要在上游加一步预处理？
      如果没有重复，提示词必须能兜住「横幅只出现一次、后面是空格」这种最坏情况。
4. **模型走本地 / 私有化部署**（选项 B），不是云端 API。
   ⇒ 不能假设有云端那种 JSON schema 约束式结构化输出，提示词要**自足**。
   ⇒ 离线运行时没有联网的 tracing / 计费面板，可观测性要自己留痕。

5. **输出形状：逐表**（`tables: [{range, columns}]`），不是拍平的列表。
   理由有实测证据：拍平形状在验证器那边**判 `partial`、覆盖率 0%**（它拒绝给通过，因为
   无法发现切分错误）；逐表形状能逐表给 `match`，且**能指出是哪张表错了**。
   而「表格范围的框定」正是这个项目最想核验的东西，拍平会把它丢掉。
6. **模型接入：公司内网的 OpenAI 兼容网关**（选项 C），**网关与模型选型不在本组件考虑范围内**。
   ⇒ 设计上把它做成**配置**：模型名、`base_url`、密钥、超时、并发全是配置项。
   ⇒ **不依赖**网关是否支持 `response_format` 约束式结构化输出；支持就是可选加速，
     **无论如何代码侧都要有兜底解析**（剥围栏、截断容错、逐条报错）。换模型不改代码。
7. **`range` 的来源是不确定的**：md 里**不一定**带 Excel 坐标，但**输入 jsonl 里可能有**。
   ⇒ 所以本组件**不能假设**坐标一定可得，也**绝不能编造**坐标。
   ⇒ 待定：输入记录到底有哪些字段（见下）。

## 需要记住的既有结论

- `excel-to-md` 的 `load_claimed` **只读它认识的键，对多余的键不报错** —— 所以往输出里加
  `provenance` 之类的字段**不会**破坏契约。
- 反过来它**会**明确报错的形状：缺 `sheet`、`columns` 不是数组、同时给 `columns` 与
  `tables`、`tables` 项缺 `range`。这些都在 `excel-to-md` 的规格里有记载。
- 别名：列名认 `columns`/`列名`，工作表认 `sheet`/`Sheet`。
